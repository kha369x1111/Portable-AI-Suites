## 1. المعمارية

```
┌───────────────────────────────────────────────────────────────┐
│  الجهاز المضيف (بلا إنترنت)                                    │
│                                                               │
│  START-Windows.bat / START-Mac-Linux.sh                       │
│        │  يقرأ config/settings.conf                           │
│        ▼                                                      │
│  bin/<OS>/llama-server  ──▶  يستمع على 127.0.0.1:8803     │
│        │                       (loopback فقط — لا وصول خارجي)  │
│        │  HTTP: /v1/chat/completions  (متوافق مع OpenAI API)   │
│        │          /v1/models · /health · /completion           │
│        ▼                                                      │
│  ui/index.html  (يُفتح كملف محلي في المتصفح)                   │
│        │  fetch → http://127.0.0.1:8803/v1/...            │
│        │  (llama-server يرسل ترويسة CORS: * فيقبل المتصفح      │
│        │   الصفحة المحلية الاتصال)                              │
│        ▼                                                      │
│  عرض المحادثة (بث مباشر SSE) + الأدوات 🧠 أوضاع النقاش       │
└───────────────────────────────────────────────────────────────┘
```

**قرارات تصميم جوهرية:**

| القرار | السبب |
|---|---|
| llama.cpp بدل Ollama | Ollama يتطلب تثبيت خدمة على النظام؛ llama-server ملف تنفيذي واحد يعمل من الفلاشة مباشرة (Zero-Dependency) |
| الواجهة ملف HTML محلي بدل خادم ويب | لا حاجة لأي خادم إضافي؛ llama-server يدعم CORS فيقبل الصفحة المحلية الاتصال به |
| ربط المحرك بـ 127.0.0.1 | يستحيل على أي جهاز آخر في الشبكة الوصول للمحرك |
| لا تثبيت ولا سجل ولا خدمة | إزالة الفلاشة = لا أثر على الجهاز المضيف |

## 2. سطر التشغيل الكامل وشرح كل وسيط

السكربت ينفّذ في النهاية:

```bash
llama-server -m models/MODEL.gguf --host 127.0.0.1 --port 8803 \
             -c 8192 --temp 0.8 --jinja [-t N] [-ngl 0]
```

| الوسيط | القيمة الافتراضية هنا | الشرح |
|---|---|---|
| `-m` | أكبر ملف .gguf في models/ | مسار النموذج |
| `--host` | `127.0.0.1` | لا تغيّرها أبداً إلا لاختبار محلي متقدم — `0.0.0.0` يكشف الخدمة للشبكة |
| `--port` | `8803` | منفذ المنتج (لكل منتج منفذ فريد) |
| `-c` | `8192` | نافذة السياق بالرموز — مجموع (مستندات + محادثة + رد) |
| `--temp` | `0.8` | درجة الحرارة |
| `--jinja` | مفعّل | يستخدم قالب المحادثة المدمج في ملف GGUF — **ضروري** لمعظم النماذج الحديثة (بدونه تفسد محادثات Qwen/Gemma) |
| `-t` | تلقائي | عدد الخيوط؛ جرّب نصف الأنوية الفعلية إذا كان الجهاز يبطئ أثناء التشغيل |
| `-ngl` | تلقائي | عدد طبقات النموذج على GPU؛ `AUTO` يضعها كلها على GPU إن وُجد، `0` يعطّل GPU كلياً |

**وسائط اختيارية مفيدة** (أضفها في `EXTRA_ARGS` بـ `config/settings.conf`):

| الوسيط | الفائدة |
|---|---|
| `-fa on` | Flash Attention — تسريع ملحوظ مع السياقات الطويلة (إن دعمه عتادك) |
| `--mlock` | تثبيت النموذج في RAM (يمنع التبديل للقرص بعد الخمول) |
| `--api-key SECRET` | يطلب مفتاحاً لكل طلب API — طبقة حماية إضافية |
| `--no-webui` | تعطيل واجهة llama-server المدمجة والاكتفاء بواجهة المنتج |
| `--cache-reuse 256` | إعادة استخدام ذاكرة KV — يسرّع الرسائل المتتالية المتشابهة |

## 3. الكمّات (Quantization) — أي ملف GGUF تختار؟

نفس النموذج يُنشر بعدة مستويات ضغط. القاعدة: **Q4_K_M هو التوازن الذهبي** (فقد جودة شبه معدوم، نصف الحجم تقريباً).

| المستوى | الحجم النسبي | الجودة | متى تستخدمه |
|---|---|---|---|
| Q8_0 | 100% | ممتازة | RAM وفيرة وجودة قصوى |
| **Q6_K** | ~78% | شبه كاملة | بديل ذكي عند توفر RAM |
| **Q4_K_M** ⭐ | ~55% | فقد ضئيل جداً | **الخيار الافتراضي الموصى به** |
| Q4_K_S / IQ4_XS | ~50% | جيدة | توفير مساحة إضافي |
| Q3_K_M | ~42% | ملحوظة الفقد | أجهزة ضيقة RAM فقط |
| IQ2_XS وأقل | ~30% | ضعيفة | طوارئ فقط — تجنبها للتحليل الجاد |

خطوة القياس الفعلية: إذا كان ملف Q4_K_M حجمه 9GB فستحتاج ≈ 10-11GB RAM حقيقية (النموذج + سياق 8192 + نظام التشغيل).

## 4. تحديث النموذج أو استبداله

### استبدال بنموذج آخر جاهز (GGUF)
1. حمّل الملف الجديد (جهازك المتصل بالإنترنت أو أي جهاز آخر) — من صفحات Hugging Face بصيغة `GGUF`.
2. انسخه إلى `models/` بجانب القديم (أو احذف القديم لتحرير المساحة).
3. في `config/settings.conf`:
   - `MODEL_FILE=اسم-الملف.gguf` لتحديده صراحة، أو
   - `MODEL_FILE=AUTO` ليُختار **الأكبر حجماً** تلقائياً (احذف القديم إذا استخدمت AUTO).
4. أعد تشغيل `START`.

### الترقية إلى نسخة أحدث من نفس النموذج
نفس الخطوات — النظام لا يهتم بالأسماء؛ أي ملف `.gguf` صالح هيكلياً سيعمل.

### تحويل نماذج أخرى إلى GGUF (متقدم)
```bash
# على جهاز فيه Python + مستودع llama.cpp:
python convert_hf_to_gguf.py /path/to/hf-model --outfile model.gguf
./llama-quantize model.gguf model-Q4_K_M.gguf Q4_K_M
```

## 5. تحديث المحرك (llama.cpp)

- **Windows:** أعد تشغيل `SETUP-Windows.bat` ووافق على تنزيل بناء حديث (يمسح القديم تلقائياً).
- **macOS (Homebrew):** `brew upgrade llama.cpp` ثم أعد تشغيل `SETUP-Mac-Linux.sh` ووافق على إعادة النسخ.
- **macOS/Linux (المصدر):** أعد تشغيل `SETUP-Mac-Linux.sh` واختر إعادة البناء.

> llama.cpp يتطور أسبوعياً؛ تحديثه شهرياً يمنحك غالباً تسريعاً مجانياً.

## 6. واجهة API — لأنك قد تحتاجها

المحرك يقدم واجهة **متوافقة مع OpenAI** على `http://127.0.0.1:8803/v1`:

```bash
# أسماء النماذج المتاحة
curl http://127.0.0.1:8803/v1/models

# محادثة (بث مباشر)
curl http://127.0.0.1:8803/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"لخص هذا العقد: ..."}],
       "temperature":0.3, "stream":true}'

# حالة الجهوزية
curl http://127.0.0.1:8803/health
```

### الاستخدام البرمجي
نفس واجهة OpenAI على `http://127.0.0.1:8803/v1` — مفيد لبناء خطوط معالجة بحثية (توليد أسئلة استبيان، تصنيف حجج، تلخيص دفعات) دون إنترنت.

## 7. ضبط الأداء

| الحالة | الإجراء |
|---|---|
| ردود بطيئة على معالج حديث | ثبّت بنية Vulkan/CUDA عبر SETUP؛ أو قلل `-c` |
| الجهاز يتجمد أثناء التشغيل | `-t` = نصف الأنوية؛ أو نموذج أصغر؛ أو `GPU_LAYERS=0` |
| استهلاك RAM مرتفع | قلل `CONTEXT_SIZE` تدريجياً (السياق يستهلك RAM خطياً) |
| أول رد بطيء والبقية سريعة | طبيعي — تحميل النموذج من الفلاشة للذاكرة؛ `--mlock` يبقيه محمّلاً |
| بطء قراءة من فلاشة USB 2.0 | استخدم SSD خارجي أو منفذ USB 3.0 — الفرق قد يكون ×10 |

## 8. الأمان — ما يحدث على الشبكة بالضبط؟

- الاستماع على `127.0.0.1` فقط. تحقق بنفسك:
  - Windows: `netstat -ano | findstr 8803` ← يجب أن ترى `127.0.0.1:8803` فقط
  - macOS/Linux: `ss -tlnp | grep 8803` أو `lsof -i :8803`
- **تحذير متوقع في السجل:** `no API key is set and CORS allows all origins` — هذا إشعار طبيعي وليس خطأ: خادم CORS المفتوح هو ما يسمح لصفحة الواجهة المحلية (`ui/index.html` المفتوحة كملف) بالاتصال بالمحرك. لا يعني ذلك السماح لأي جهاز خارجي — الاستماع يبقى على `127.0.0.1` حصراً.
- لا تلمترية ولا اتصال صادر في llama-server أو الواجهة (يمكنك التحقق بجدار حماية صادر Allow-127.0.0.1 فقط).
- الواجهة ملفات ثابتة — لا كوكيز تتبع، لا CDN خارجي، لا خطوط ويب.
- الوضع الأمثل للخصوصية القصوى: شغّل الجهاز والشبكة اللاسلكية **مطفأة تماماً** — المنتج مصمم لذلك.
- `--api-key` في `EXTRA_ARGS` يضيف حاجزاً حتى أمام العمليات المحلية الأخرى (لن تحتاجه مع واجهة المنتج).

## 10. حل مشكلات المحرك المتقدمة

```bash
# تشغيل المحرك يدوياً لرؤية الأخطاء مباشرة (بدون START):
./bin/linux/llama-server -m models/FILE.gguf --port 8803 --jinja

# فحص ملف النموذج نفسه:
./bin/linux/llama-server --version
# ملف تالف عادة يعطي "failed to load model" في engine.log

# أذونات لينكس/ماك:
chmod +x bin/*/llama-server   # إذا نسخته يدوياً لنظام ملفات يدعم التنفيذ
```

| رسالة في engine.log | المعنى |
|---|---|
| `not enough memory` | النموذج أكبر من RAM — خذ كمّاً أصغر |
| `unknown model architecture` | محرك قديم لنموذج حديث — حدّث المحرك (قسم 5) |
| `failed to load model` غالباً | ملف ناقص/تالف — أعد التنزيل (SETUP يستأنف تلقائياً) |
| `listen: address already in use` | المنفذ مشغول — غيّر PORT |
| تحذيرات GGML metadata | غير قاتلة عادة — تجاهلها |
